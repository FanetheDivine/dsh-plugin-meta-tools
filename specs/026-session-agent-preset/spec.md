## Clarifications

### Session 2026-11-21

- Q: “新增会话”区域的模型标签如何调整？ → A: 把“默认模型”改为“模型”。
- Q: 预设控制放在哪里、用什么形态？ → A: 放在模型下方，标签“预设”，描述“选择新建会话时使用的预设”，右侧一个 select，浮窗使用 DSH 自带 Menu。
- Q: 未选择预设时使用什么？ → A: 跟随宿主默认；菜单首项“跟随宿主默认”用于恢复未选择状态。
- Q: 已保存的预设不可用时如何处理？ → A: 配置页保留并标注不可用；新建会话创建时从宿主读取可用预设，配置值在其中就使用，否则按未配置处理并跟随宿主默认。
- Q: 显式传入的预设不可用时如何处理？ → A: 保持现有行为，由宿主拒绝并返回可理解的错误。
- Q: 宿主未提供预设名册时如何表现？ → A: 选择器禁用并说明原因；新建会话沿用宿主行为。
- Q: 关闭 `session_create` 时选择器是否可编辑？ → A: 始终可编辑，与模型选择一致。
- Q: 插件默认预设的作用范围？ → A: 只影响 AI 新建会话；不修改宿主“新任务默认预设”。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在配置页选择新增会话的预设 (Priority: P1)

用户在“元工具”配置页的“新增会话”区域看到“模型”与“预设”两行。预设行右侧是 select，点击后弹出宿主 Menu，列出可用预设和“跟随宿主默认”。选择并保存后成为插件默认预设。

**Why this priority**: 这是本次需求的直接目标：在配置页为新会话选择预设。

**Independent Test**: 打开配置页，检查两行文案与位置，打开预设菜单选择一项并保存，重新打开配置页确认选择保留。

**Acceptance Scenarios**:

1. **Given** 配置页打开，**When** 查看“新增会话”区域，**Then** 第一行标签为“模型”，其下方为“预设”行。
2. **Given** “预设”行显示，**When** 查看文案，**Then** 标签为“预设”，说明为“选择新建会话时使用的预设”，右侧为 select 触发器。
3. **Given** 点击预设触发器，**When** 菜单打开，**Then** 浮窗为 DSH 自带 Menu，首项为“跟随宿主默认”，其后列出宿主可用预设。
4. **Given** 用户选择一个预设，**When** 保存配置，**Then** 选择被保存，后续未显式传参的新建会话使用该预设。
5. **Given** 用户修改预设，**When** 放弃草稿，**Then** 已保存值保持不变。
6. **Given** 用户选择“跟随宿主默认”，**When** 保存配置，**Then** 新建会话使用宿主默认预设。

---

### User Story 2 - 新建会话应用默认预设 (Priority: P2)

AI 新建会话时，未提供预设就使用插件默认预设；提供预设时使用显式值；未保存插件默认时沿用宿主默认。

**Why this priority**: 默认值必须真正作用到新建会话，同时保持现有调用兼容。

**Independent Test**: 分别在保存默认预设、显式传参、未保存默认三种状态下新建会话，检查会话使用的预设。

**Acceptance Scenarios**:

1. **Given** 插件已保存默认预设，**When** 新建会话未提供预设，**Then** 新会话运行该预设。
2. **Given** 插件已保存默认预设，**When** 新建会话显式提供预设，**Then** 新会话运行显式预设。
3. **Given** 插件未保存默认预设，**When** 新建会话未提供预设，**Then** 新会话沿用宿主默认，其他行为不变。
4. **Given** 预设与工作区、目录、模型、标题或首条消息同时提供，**When** 新建会话，**Then** 各项能力独立生效。
5. **Given** 显式指定的预设不可用，**When** 新建会话，**Then** 创建返回可理解的错误，不设置标题、不投递首条消息。
6. **Given** 已保存的默认预设不在宿主可用名册中，**When** 新建会话未显式提供预设，**Then** 使用宿主默认预设创建，不返回预设错误。

---

### User Story 3 - 不可用状态与降级 (Priority: P3)

已保存的预设从名册消失或损坏时，用户仍能在配置页看到它并重新选择；名册加载失败或宿主不提供预设时，配置页给出明确状态。

**Why this priority**: 预设名册随部署变化，配置不能静默失效或让用户无从选择。

**Independent Test**: 保存一个预设后使其不可用，打开配置页检查标注；替换为可用预设后新建会话恢复正常。

**Acceptance Scenarios**:

1. **Given** 已保存预设从名册消失或标记为损坏，**When** 打开配置页，**Then** 触发器显示该预设并标注不可用，其余可用预设仍可选择。
2. **Given** 预设名册加载失败，**When** 打开配置页，**Then** 显示加载失败与重试，已保存值保留。
3. **Given** 宿主不提供预设名册，**When** 打开配置页，**Then** 选择器禁用并说明原因。
4. **Given** 已保存预设不可用，**When** 用户重新选择可用预设并保存，**Then** 后续新建会话恢复正常。
5. **Given** 已保存预设不可用，**When** 新建会话未显式提供预设，**Then** 使用宿主默认预设创建，配置值保持不变。

---

### Edge Cases

- 预设名册为空时，菜单只有“跟随宿主默认”。
- 预设名称缺失或只含空白时，菜单与触发器显示预设标识。
- 预设名称变化、标识不变时，选择保持不变，显示更新后的名称。
- 插件默认预设与宿主默认是同一预设时，正常保存与使用。
- 已保存预设损坏（名册标记不可用）时，触发器标注不可用，菜单仍允许另选。
- 已保存预设不可用时，新建会话按未配置处理并跟随宿主默认，配置值保持不变。
- 清空预设选择时，保存为空值并显示“跟随宿主默认”。
- 菜单打开时，浮窗不被配置页容器裁切，并按可用空间滚动。
- 菜单支持键盘：方向键移动、回车确认、Esc 关闭并返回触发器焦点。
- 配置页只读、保存失败或热更新时，预设行与模型行表现一致。
- 关闭 `session_create` 时预设配置保留但不生效；重新开启后直接生效。
- 默认预设与默认模型互不影响，可分别设置或清空。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 配置页“新增会话”区域的模型标签 MUST 为“模型”。
- **FR-002**: 配置页 MUST 在模型行下方新增“预设”行，标签为“预设”，说明为“选择新建会话时使用的预设”。
- **FR-003**: 预设行右侧 MUST 提供 select 触发器，浮窗使用 DSH 自带 Menu。
- **FR-004**: 菜单 MUST 首项提供“跟随宿主默认”，其后按名册顺序列出宿主可用预设。
- **FR-005**: 触发器 MUST 显示当前预设名称；未选择时显示“跟随宿主默认”；已保存但不可用时标注不可用。
- **FR-006**: 预设选择 MUST 只修改配置草稿，保存后生效，放弃草稿时恢复已保存值。
- **FR-007**: 保存的默认预设 MUST 在宿主可用名册中存在时，用于未显式提供预设的新建会话。
- **FR-008**: 显式预设参数 MUST 覆盖插件默认预设，两者不合并。
- **FR-009**: 未保存插件默认预设时，新建会话 MUST 沿用宿主默认，现有参数、返回结果与行为保持兼容。
- **FR-010**: 不可用的默认预设 MUST 在创建时按未配置处理并使用宿主默认，不阻断创建；显式传入的无效预设 MUST 返回可理解的错误。
- **FR-011**: 名册加载失败 MUST 显示失败状态与重试；宿主不提供预设名册时 MUST 禁用选择器并说明原因。
- **FR-012**: 菜单 MUST 支持键盘操作，浮窗 MUST 不被配置页容器裁切。
- **FR-013**: 预设选择器 MUST 始终可编辑，与模型选择一致；关闭 `session_create` 时配置保留但不生效。
- **FR-014**: 插件默认预设 MUST 只影响工具创建的新会话，不修改宿主“新任务默认预设”。
- **FR-015**: 默认预设与默认模型 MUST 相互独立，可分别设置、清空与覆盖。
- **FR-016**: 选择器 MUST 只读展示预设名册，不提供预设的新建、编辑或删除。

### Key Entities *(include if feature involves data)*

- **默认预设配置**: 插件保存的预设标识；空值表示跟随宿主默认。
- **预设名册**: 宿主提供的预设列表，含标识、名称、说明、默认标记与可用状态。
- **预设菜单项**: “跟随宿主默认”项与每个预设项；不可用的已保存项额外标注。
- **新会话**: 使用插件默认预设、显式预设或宿主默认预设执行的会话。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 的配置页在“新增会话”区域显示“模型”与“预设”两行，文案与位置符合需求。
- **SC-002**: 100% 已保存默认预设且未显式传参的新建会话请求，使用该预设运行。
- **SC-003**: 100% 显式传参的新建会话请求，使用显式预设运行。
- **SC-004**: 100% 未保存默认预设且未传参的新建会话请求，保持现有行为。
- **SC-005**: 用户一次保存即可让后续未传参的新建会话使用所选预设。
- **SC-006**: 100% 已保存但不可用的预设能在配置页看到并替换，无需手工修改配置文件。
- **SC-007**: 100% 的预设保存操作不改变宿主“新任务默认预设”。
- **SC-008**: 100% 已保存默认预设不在可用名册中的新建会话请求，使用宿主默认预设创建。

## Assumptions

- 宿主提供预设名册，包含每个预设的标识、名称与可用状态。
- 宿主在创建会话前可读取可用预设名册；只有可用预设会应用到新建会话。
- 预设以标识区分，名称只用于显示。
- DSH 自带的 Menu 与远程预设名册可在插件配置页复用。
- 空配置表示跟随宿主默认。
- 插件默认预设与宿主“新任务默认预设”相互独立。
- 本需求只扩展新增会话能力，不提供修改已有会话预设的能力。
