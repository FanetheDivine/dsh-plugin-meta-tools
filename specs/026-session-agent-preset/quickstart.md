# Quickstart: 配置新增会话的预设

## 前置条件

- Node.js 24.9+ 与 pnpm 11.7。
- `@deepseek-ai/dsh-*` 依赖已升级到 `0.2.2-rc.5`。
- 已运行 `pnpm install`。

## 命令

```sh
pnpm install
pnpm format
pnpm check
pnpm build
pnpm full-check
```

## 场景

### 1. 配置页界面

1. 打开“插件”页的“元工具”配置。
2. “新增会话”区域第一行标签为“模型”，其下为“预设”。
3. 预设行说明为“选择新建会话时使用的预设”，右侧为 select 触发器。
4. 点击触发器，确认浮窗为 DSH 自带 Menu，首项“跟随宿主默认”，其后为可用预设。

**预期**：布局、文案与菜单顺序符合契约；浮窗不被容器裁切。

### 2. 保存默认预设

1. 在预设菜单选择一个可用预设。
2. 保存配置。
3. 重新打开配置页。

**预期**：触发器显示所选预设，保存值在重开后保持。

### 3. 新建会话使用默认预设

1. 保存默认预设。
2. 让 AI 调用 `session_create`，不传 `agent_preset`。
3. 读取新会话头部。

**预期**：会话记录的预设为所选预设。

### 4. 显式参数覆盖

1. 保存默认预设。
2. 调用 `session_create` 并显式传入另一个可用预设。

**预期**：会话使用显式预设。

### 5. 不可用预设回退

1. 保存一个预设后使其从名册消失或损坏。
2. 打开配置页：触发器标注“不可用”。
3. 不传 `agent_preset` 新建会话。

**预期**：配置页保留并标注；新建会话改用宿主默认，不返回预设错误；配置值不变。

### 6. 名册不可用

1. 在未组合预设的部署打开配置页。
2. 新建会话。

**预期**：选择器禁用并说明原因；新建会话沿用宿主行为。

## 真实宿主验证

- 在 Desktop 与 Web 宿主打开配置页，核对菜单键盘操作与浮层位置。
- 让 AI 新建会话，并在会话头部确认预设记录。
- 确认宿主“新任务默认预设”未被插件修改。
