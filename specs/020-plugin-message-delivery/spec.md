# Feature Specification: 插件消息投递约束

**Feature Branch**: `fix/020-plugin-message-delivery`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "投递消息不要用session.prompt kind不能是user 必须是插件名称；投投递时只允许插话 去掉相关的参数"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 以插件身份插话 (Priority: P1)

操作者通过消息投递能力向目标会话发送消息，接收方将其识别为当前插件发起的插话。

**Why this priority**: 正确的消息来源和投递方式决定宿主能否按预期处理消息。

**Independent Test**: 向一个目标会话投递一条消息，检查接收记录中的来源类型、来源名称和投递方式。

**Acceptance Scenarios**:

1. **Given** 一个可接收消息的目标会话， **When** 当前插件投递消息， **Then** 消息以插话方式进入目标会话。
2. **Given** 一个可接收消息的目标会话， **When** 当前插件投递消息， **Then** 来源类型等于当前插件名称，消息不会归属为用户。
3. **Given** 一次有效的消息投递， **When** 宿主处理该消息， **Then** 投递过程使用宿主为插件消息提供的通道。
4. **Given** 一个需要非插件来源的 subagent 目标， **When** 操作者尝试投递， **Then** 系统返回宿主归属错误且不改用其他来源。

---

### User Story 2 - 使用单一的投递方式 (Priority: P2)

操作者只需提供消息目标和内容，无需选择投递方式或填写其他投递方式专用的信息。

**Why this priority**: 单一投递方式让调用约束清晰，并避免产生宿主不支持的投递请求。

**Independent Test**: 查看消息投递能力所需的输入，分别完成一次有效调用和一次包含已移除选项的调用。

**Acceptance Scenarios**:

1. **Given** 操作者准备投递消息， **When** 查看可填写的信息， **Then** 只需提供目标和内容等插话所需的信息。
2. **Given** 消息投递能力已发布， **When** 检查投递方式及其他投递方式的专用选项， **Then** 这些选项均已移除。

### Edge Cases

- 调用方继续提供已移除的选项时，这些选项不属于有效的投递输入。
- 目标会话不可用或归属 subagent 专用路由时，现有宿主错误保持不变，消息不会改以其他来源投递。
- 投递内容为空或目标无效时，沿用现有输入校验。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 通过宿主提供的插件消息通道投递消息。
- **FR-002**: 系统 MUST 将每条投递消息的来源类型设置为当前插件名称。
- **FR-003**: 系统 MUST 将每条投递消息标记为插话。
- **FR-004**: 系统 MUST 将消息归属于当前插件，不能归属于用户。
- **FR-005**: 消息投递能力 MUST 只支持插话，并移除投递方式选择项。
- **FR-006**: 系统 MUST 移除仅服务于其他投递方式的输入项，保留插话所需的目标与内容输入。
- **FR-007**: 系统 MUST 保持目标不可用、目标无效和内容无效的现有错误处理行为。
- **FR-008**: 系统 MUST 拒绝需要非插件来源的投递目标，确保全部成功投递均使用当前插件名称作为来源类型。
- **FR-009**: 新建会话时由本插件投递的可选首条消息 MUST 遵循相同的插话与插件来源约束。

### Key Entities

- **投递消息**: 包含目标会话、消息内容、插话方式和插件来源标识。
- **当前插件**: 消息的实际发起方，其名称同时作为消息来源类型。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 的有效投递以插话方式进入目标会话。
- **SC-002**: 100% 的有效投递以来源类型等于当前插件名称的形式记录，用户来源记录为 0。
- **SC-003**: 发布后的投递输入中，投递方式和其他投递方式专用选项的数量为 0。
- **SC-004**: 目标与内容的既有校验用例全部保持原有结果。

## Assumptions

- 当前插件名称取自插件已有的稳定身份，无需增加配置。
- 本次范围包括普通会话的消息投递、新建会话的可选首条消息及其文档和测试。
- subagent 使用宿主的专用消息路由，本次不为其保留其他来源的投递回退。
- 已移除的输入项无需兼容别名或回退行为。
- 目标会话仍由调用方指定，消息内容仍由调用方提供。
