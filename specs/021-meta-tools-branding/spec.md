## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在插件列表一眼认出元工具 (Priority: P1)

用户在“插件”页浏览插件，通过标题、描述与图标理解本插件是“元工具”：它让 AI 修改自身运行环境，例如管理工作区与会话。

**Why this priority**: 标题、描述与图标是用户决定是否启用插件时最先看到的信息。

**Independent Test**: 打开“插件”页，只看本插件的行与卡片，判断能否说出插件用途。

**Acceptance Scenarios**:

1. **Given** 界面语言为中文， **When** 用户查看本插件行， **Then** 标题为“元工具”，描述说明 AI 能借此修改自身运行环境，并点出工作区与会话。
2. **Given** 界面语言为英文， **When** 用户查看本插件行， **Then** 标题为“Meta tools”，描述表达相同含义。
3. **Given** 明暗两种主题， **When** 用户查看本插件图标， **Then** 图标清晰可辨，表达“AI 作用于自身环境”的自指含义。

---

### User Story 2 - 在详情页读懂能力与风险 (Priority: P1)

用户打开本插件详情页，读到的说明文档面向使用者：AI 获得哪些能力、适合哪些场景、如何限制这些能力、有哪些边界。

**Why this priority**: 详情页直接展示说明文档。当前文档以开发者视角罗列安装命令、配置键与参数表，用户无法据此判断价值与风险。

**Independent Test**: 让未接触过本插件的用户阅读详情页，复述 AI 可以做什么、怎样关闭某项能力。

**Acceptance Scenarios**:

1. **Given** 用户打开详情页， **When** 阅读说明， **Then** 先看到“元工具”的一句话定义，再看到按场景组织的能力说明。
2. **Given** 用户阅读说明， **When** 查找如何限制 AI， **Then** 文档指引到“插件”页的配置开关，并说明保存后立即生效。
3. **Given** 用户阅读说明， **When** 查找安全边界， **Then** 文档说明 AI 不会删除目录、会话日志与会话。
4. **Given** 用户阅读说明， **When** 通读全文， **Then** 文档不含安装命令、配置键表、工具参数与返回值表。

---

### User Story 3 - 在配置页按能力决定开放范围 (Priority: P2)

用户在配置页逐项决定向 AI 开放哪些能力。开关按能力分组，每项附一句说明，写操作能力的影响清晰可见。

**Why this priority**: 当前配置页是十一个平铺开关，部分标签与实际行为不符，例如“删除工作区”实际只移除注册。

**Independent Test**: 打开配置页，不看文档，判断每个开关关闭后 AI 失去什么能力。

**Acceptance Scenarios**:

1. **Given** 用户打开配置页， **When** 浏览开关， **Then** 开关分为“工作区”“查看会话”“管理会话”三组，每组有标题。
2. **Given** 任意一个开关， **When** 用户阅读该项， **Then** 看到准确的能力标签与一句说明。
3. **Given** 移除工作区的开关， **When** 用户阅读该项， **Then** 标签与说明表明只移除注册，目录与会话保留。
4. **Given** 中英文界面， **When** 切换语言， **Then** 分组标题、标签与说明全部随语言切换。
5. **Given** 用户修改开关并保存， **When** 保存完成， **Then** 行为与现有保存流程一致。
6. **Given** 任意能力分组， **When** 用户浏览标题， **Then** 标题按一级分组突出显示。
7. **Given** 任意一个开关， **When** 用户查看该项， **Then** 工具名显示在功能名称左侧，开关紧随功能名称右侧。
8. **Given** 配置页的所有开关， **When** 用户纵向浏览， **Then** 开关位于同一竖直列。

### Edge Cases

- 宿主读取元数据时插件处于停用状态：标题、描述与图标照常显示。
- 配置页在只读部署或配置不可用时：沿用现有提示文案。
- 窄屏 390 px：配置页开关说明换行显示，开关不被挤出。
- 开发者需要的配置键、工具契约与日志目录结构：保留在开发者文档中。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 中文标题 MUST 为“元工具”，英文标题 MUST 为“Meta tools”。
- **FR-002**: 中英文描述 MUST 说明插件为 AI 提供修改自身运行环境的能力，并点出工作区与会话。
- **FR-003**: 图标 MUST 由扳手与环绕它的首尾相接箭头组成，表达工具作用于自身，在明暗主题与行尺寸下可辨识。
- **FR-004**: 图标 MUST 不绘制底板，配色与相邻已安装插件图标协调。
- **FR-005**: 说明文档 MUST 以用户视角组织：元工具定义、使用场景、能力分组、如何限制、安全边界、限制。
- **FR-006**: 说明文档 MUST 移除安装命令、配置键表与工具参数表。
- **FR-007**: 被移出说明文档的开发者信息 MUST 在开发者文档中有归属，例如配置键、工具契约与会话日志目录结构。
- **FR-008**: 配置页 MUST 把十一个开关分为“工作区”“查看会话”“管理会话”三组，并显示分组标题。
- **FR-009**: 每个开关 MUST 显示准确的能力标签与一句说明；标签同时作为开关的无障碍名称。
- **FR-010**: 配置页的全部新增文案 MUST 提供中英文两份。
- **FR-011**: 配置页一行概述 MUST 体现元工具定位。
- **FR-012**: 配置键、默认值、保存流程与工具行为 MUST 保持不变。
- **FR-013**: 分组标题 MUST 按一级分组的视觉层级显示。
- **FR-014**: 每个开关行 MUST 显示具体工具名，工具名位于功能名称左侧。
- **FR-015**: 开关 MUST 位于功能名称右侧，全部开关 MUST 竖直对齐。

### Key Entities

- **元工具**: 让 AI 修改自身运行环境的工具，作用对象是工作区与会话。
- **能力分组**: 工作区、查看会话、管理会话三组，对应配置页分组与文档章节。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 中英文标题分别等于“元工具”与“Meta tools”。
- **SC-002**: 说明文档中安装命令、配置键表与工具参数表的数量为 0。
- **SC-003**: 十一个开关 100% 有说明文案，且归入三个分组之一。
- **SC-004**: 未接触过插件的读者只读详情页，能说出至少三类 AI 可执行的操作与关闭方法。
- **SC-005**: 现有工具与配置测试全部保持通过。

## Assumptions

- 说明文档继续使用包内 `README.md`，详情页按宿主规则直接展示它；本次不新增详情图片。
- 用户要求移除 README 中的安装、配置、工具章节，与宪章原则 III 对 `README.md` 归属内容的描述冲突；按用户要求执行，并同步修订宪章表格。
- 分组划分沿用代码中已有的工具组：工作区、会话读取、会话控制与导航。
- 工具名称与参数属于模型契约，本次不改动。
