# Feature Specification: 配置新增会话的模型

**Feature Branch**: `feat/022-configure-session-model`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "要允许配置 新增session的provider/model/effort"；界面要求与 DSH 官方模型选择器一致。

## Clarifications

### Session 2026-11-19

- Q: provider/model/effort 选择器放在哪里？ → A: 放在“元工具”插件配置页，作为 AI 新建会话的默认配置；工具显式参数优先，不显示团队协作开关。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按任务选择新会话模型 (Priority: P1)

用户让 AI 新增会话时，可以指定 provider、model 和 effort，让新会话从首轮工作开始使用所需模型配置。

**Why this priority**: 不同任务需要不同模型能力与推理强度。新增会话目前无法选择这些配置，限制了任务分派。

**Independent Test**: 使用一组有效的 provider、model 和 effort 新增会话并附带首条消息，检查新会话从首轮开始使用指定配置。

**Acceptance Scenarios**:

1. **Given** 存在有效的 provider、model 和 effort 组合，**When** 用户新增会话并同时提供三项配置，**Then** 新会话使用这三项配置。
2. **Given** 新增会话包含首条消息，**When** 用户指定模型配置，**Then** 首条消息产生的首轮工作使用该配置。
3. **Given** 用户提供 provider 和 model 并省略 effort，**When** 新增会话，**Then** 新会话使用指定路由与所选模型的默认 effort。
4. **Given** 用户未提供模型参数且插件未保存默认模型，**When** 按现有方式新增会话，**Then** 新会话沿用宿主默认选择，其他行为保持不变。
5. **Given** 插件已保存默认模型，**When** 工具显式提供完整模型参数，**Then** 新会话使用显式参数。

---

### User Story 2 - 在插件配置页设置默认模型 (Priority: P2)

用户在“元工具”配置页通过模型与推理等级选择器设置新增会话的默认配置，并保存为插件配置。

**Why this priority**: 常用模型只需设置一次。用户无需在每次任务分派时重复提供参数。

**Independent Test**: 打开插件配置页，选择带 provider 标识的模型和 effort，保存后新增不附带模型参数的会话，检查会话使用已保存配置。

**Acceptance Scenarios**:

1. **Given** 模型目录可用，**When** 用户打开模型选择器，**Then** 界面呈现与 DSH 官方一致的模型和推理等级两级菜单。
2. **Given** 用户查看模型触发器、当前值或模型选项，**When** 模型已选择或列出，**Then** provider 显示在模型名称前。
3. **Given** 所选模型提供推理等级，**When** 用户打开推理等级选择器，**Then** 只显示该模型支持的等级。
4. **Given** 用户修改模型或 effort，**When** 保存配置，**Then** 新默认值用于后续未显式指定模型的新增会话。
5. **Given** 用户修改模型或 effort，**When** 放弃草稿，**Then** 已保存配置保持不变。
6. **Given** 配置页显示模型选择器，**When** 查看其根菜单，**Then** 只包含模型与适用的推理等级控制，不包含团队协作开关。

### Edge Cases

- provider、model 或 effort 只包含空白字符时，按未提供处理。
- 只提供 provider 或 model 时，请求在创建会话前返回参数错误。
- 未同时提供 provider 和 model 而提供 effort 时，请求在创建会话前返回参数错误。
- provider 或 model 不可用时，请求返回可理解的错误。
- effort 不适用于所选 provider 或 model 时，请求返回可理解的错误。
- 模型配置在会话创建后失败时，错误包含新会话 id，且不设置标题或投递首条消息。
- 模型配置与工作区、目录、预设、标题或首条消息同时提供时，各项能力保持原有行为。
- 模型目录加载中、加载失败、为空或部分 provider 失败时，选择器沿用官方对应状态与重试行为。
- 所选模型没有推理元数据时，不显示推理等级控制。
- 已保存模型离开目录后，保留配置并显示未选择状态；恢复目录条目后可再次显示与使用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户 MUST 能在新增会话时同时指定 provider 与 model，并可选择 effort。
- **FR-002**: 系统 MUST 将有效的模型配置应用于新会话的首轮及后续工作。
- **FR-003**: 系统 MUST 在未提供工具模型参数时使用插件默认模型；插件默认值也为空时使用宿主默认选择。省略 effort 时使用所选模型的默认值。
- **FR-004**: 系统 MUST 在设置标题与投递首条消息前完成模型配置。
- **FR-005**: 系统 MUST 拒绝不完整或无效的模型配置，并返回可理解的错误。
- **FR-006**: 新增模型配置 MUST 保持现有新增会话调用的兼容性；现有参数、返回结果与未保存插件默认值时的行为保持兼容。
- **FR-007**: 模型配置失败时，系统 MUST 停止后续标题设置与首条消息投递；会话已创建时，错误 MUST 包含新会话 id。
- **FR-008**: 模型配置 MUST 只作用于新会话，不修改宿主全局默认模型。
- **FR-009**: 插件配置页 MUST 使用与 DSH 官方一致的模型与推理等级选择器，并支持目录加载、搜索、键盘操作、错误与空状态。
- **FR-010**: 模型触发器、根菜单当前值与模型选项 MUST 把 provider 显示在模型名称前。
- **FR-011**: 推理等级选择器 MUST 只提供所选模型支持的等级；模型没有推理元数据时隐藏该控制。
- **FR-012**: 插件模型选择器 MUST 只显示模型与适用的推理等级控制，不提供团队协作配置项。
- **FR-013**: 模型配置 MUST 遵循配置页现有草稿、保存、放弃、只读与热更新行为。
- **FR-014**: 工具显式模型参数 MUST 覆盖插件默认模型，且不与插件默认值合并。

### Key Entities *(include if feature involves data)*

- **模型配置**: 新增会话的模型选择，包含成对的 provider、model 与可选的 effort。
- **插件默认模型**: 配置页保存的模型配置，供未显式传参的新增会话使用。
- **模型目录**: 按 provider 分组的可用模型及各自支持的 effort。
- **新会话**: 使用模型配置执行的会话，可同时具有工作区、目录、预设、标题与首条消息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 使用有效 provider、model 和 effort 的新增会话请求，从首轮开始应用所请求的配置。
- **SC-002**: 100% 未保存插件默认值且省略模型参数的现有新增会话请求保持原有行为。
- **SC-003**: 100% 无效模型配置请求返回明确失败结果，且不投递首条消息。
- **SC-004**: 用户只需一次新增会话请求即可完成模型选择，无需创建后再次配置。
- **SC-005**: 100% 指定模型配置的新增会话请求保持宿主全局默认模型不变。
- **SC-006**: 用户在一次保存后，即可让后续所有未显式传参的新增会话使用所选默认模型。
- **SC-007**: 100% 模型触发器、当前值与选项在模型名前显示 provider，且根菜单不含团队协作配置项。

## Assumptions

- 宿主提供会话级模型选择、模型目录与配置校验能力。
- provider 与 model 使用宿主支持的标识，并组成完整路由。
- effort 的可用值由所选 provider 与 model 决定。
- 插件默认模型与宿主全局默认模型相互独立。
- 本需求只扩展新增会话能力，不提供修改已有会话模型配置的能力。
