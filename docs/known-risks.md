# 已知风险

## 宿主版本

- `@deepseek-ai/dsh-*` 处于 rc 阶段，接口可能在版本间变化。
- 插件依赖的版本应与运行它的 DSH 版本一致；当前固定为 0.2.2-rc.5。
- `sessionController`、`workspaceRegistry` 与预设注册表接口按 0.2.2-rc.5 实现，升级宿主后需要重新运行 `pnpm check` 与实机验证。
- `@deepseek-ai/dsh-*` 依赖未列入 `minimumReleaseAgeExclude` 时，`pnpm install` 失败。
- 版本与列入规则见[宪章](../.specify/memory/constitution.md)原则 I。

## 共享宿主实例

宿主提供的依赖被打进 bundle 时会产生第二份实例，类型判断和服务注入随之失效。依赖归属与保持 external 的规则见 [how-it-works.md](./how-it-works.md#依赖复用)。

## 可选服务

- `workspaceRegistry`、`sessionQuery`、`sessionController` 缺失时，对应工具不注册；插件照常加载。
- 模型看不到某个工具时，先检查部署是否组合了对应服务，再检查开关。
- 服务晚到时工具组补注册；服务卸载时整组释放。
- `sessions` 缺失时不影响导出，只是跳过落盘屏障；可能读到较旧的已落盘日志。
- `llm` 缺失时不影响现有创建流程，但指定模型的新建会话会在创建前失败。
- `agentPresets` 缺失时默认预设按空值处理，新建会话沿用宿主默认。

## 同名工具冲突

- 本插件与 `@local/dsh-harness-tools` 注册同名工具，同一部署只能保留一个插件行。
- 同时启用时后者注册失败或覆盖，取决于加载顺序；安装本插件前先移除旧行。
- 本插件的 `session_get` 契约与旧实现不同，外部说明需要同步更新。

## 标题查询

- `session_list` 的 `query` 需要折叠标题，每个标题都要读日志。
- 单次查询最多折叠最新 200 个候选会话；超过时结果附说明。
- 大历史下先按工作区或目录缩小范围，或省略 `query`。
- 标题读取失败只影响匹配，列表仍返回其余会话；整批失败时附 `note`。

## 会话日志导出

- 日志写入系统临时目录，不写工作区；不返回消息正文。
- 每次调用新建独立目录，历史目录由操作系统清理，插件不主动删除。
- 临时目录可能被清理策略回收，长时间任务应尽快读取。
- 导出不包含图片与附件；日志里的附件引用保持原样。
- 大日志会占用磁盘与时间；按会话逐个读取，单个会话失败即整体失败。
- 临时目录不可写时导出失败，错误带上底层原因。
- 在受限沙箱中，模型读取系统临时目录可能被拒绝；需要放宽文件策略或改读工作区副本。

## 会话操作

- `session_stop` 只取消当前轮次，排队消息保留；空闲会话视为已接受。
- 归档运行中的会话默认被拒绝；传 `stop_activity: true` 会停止其工作。
- 置顶要求会话存在且未归档；归档会移除置顶。
- 插件默认预设只在宿主可用名册中生效；预设在保存后被移除或损坏时，新建会话静默回退宿主默认，配置页仍保留并标注不可用。
- 显式 `agent_preset` 保持宿主校验；无效值会让创建失败。
- 模型配置在创建前校验失败时不会创建会话；创建后选择失败时，错误会带出会话 id，标题与首条消息不会继续处理。
- 新建会话已创建但首条消息失败时，错误会带出会话 id，需要后续重试。
- 发送消息默认排队；`steer` 只在最近一步投递，目标空闲时按队列处理。
- subagent 目标的发送与停止走子代理路由，调用方必须是它的祖先；否则被拒绝。
- `system-reminder` 包裹是文本约定，目标会话看到的是一段用户消息。

## 工作区目录

- 目录被移动或删除时，注册记录仍在，`workspace_list` 返回 `status: missing-dir`。
- `workspace_remove` 不清理目录，也不删除会话日志。

## 严格配置

- 配置中出现未知键、工具开关非布尔值、默认模型字段非字符串或 provider/model 未成对时，插件加载失败。
- 用户在 `cordis.patch.yml` 写错键名会导致插件停用。
- 用 `dsh --profile <profile> --dump-config` 检查最终配置。

## 前端

- 配置页依赖 `dsh-client-ui-plugin-manager` 与 `dsh-client-ui-settings`；宿主未加载这些包时配置页不出现。
- `PLATFORM_MODULES` 是宿主冻结模块表的副本；宿主升级后需要核对。
- 配置页键是 `<包名>#<行 id>`；包名或行 id 变化时两处都要改。
- 客户端依赖版本与宿主不一致时，槽位或 locale 服务可能不可用。
- 默认模型选择器复用官方包的源码子路径，升级宿主后需要重新检查组件 props、模型目录与 CSS 构建。

## 国际化

- 宿主在注册时捕获的文案（如命令描述）保持注册时的语言，切换语言后仍显示旧语言；槽位渲染的文案随切换更新。
- locale 服务只负责选择、持久化、语言匹配、键回退与 `<html lang>`；复数规则与双向布局由语言包自理。
- 元数据或字典缺当前语言时按回退链取值；缺 `meta.title` 与 `meta.description` 时回落 `package.json` 的字段，可能显示英文包名。
- 规范见 [i18n.md](./i18n.md)。

## Windows 长路径

`node_modules` 嵌套很深，路径可能超过 Windows 的 260 字符上限。

- `git worktree remove` 此时报错 `Filename too long`。
- `finish-worktree.sh` 遇到该错误时用 Node.js `rmSync` 删除目录，再运行 `git worktree prune`。
